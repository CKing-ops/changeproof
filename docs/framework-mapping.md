# Framework mapping

Generated by `scripts/framework_mapping.py` from `src/changeproof/frameworks.py`. Do not edit by hand.

changeproof's evidence comes in two halves that answer change-management controls together:

1. **What the change touches.** The impact predicate lists every entity that depends on the changed
   code, with a confidence tier and the dependency path to each one (Week 5, `tests/test_impact.py`).
2. **Evidence that nothing else changed behaviour.** A behavioral-equivalence attestation replays
   characterization tests from the base at the head for the code outside that impact set (Weeks 8-9,
   `tests/test_equivalence.py`). It is tested equivalence, not a proof for all inputs, and it covers
   COBOL linkage subprograms only.

Each control lists the engine output that answers it and the test or exit check that proves the
engine produces that output. Outputs marked **planned** are not built yet.

**Status** is about the control itself. "checked" with a date means its ID and topic were read in
the linked source text on that date. **unverified** means they were not: they come from the
project's own knowledge and must be checked against the source before anyone relies on them
(project rule 6). The topic column is our own short label, not the control's wording.

Checked so far: the ECB IT Risk Questionnaire rows (fact-check of 2026-09-27); the Delegated
Regulation (EU) 2024/1774 rows (EUR-Lex, 2026-10-01); NIST SP 800-53 control titles, statements and
SP 800-53A objectives (NIST's OSCAL catalog), NIST SP 800-218 practices and tasks, and GDPR
Chapter V (EUR-Lex), all on 2026-10-07; CNSA 2.0 in NSA's CNSA 2.0 FAQ (v2.1) on 2026-10-14. Still
unverified: DORA itself (its wording matches a reproduction of the Official Journal, but the EUR-Lex
page is too long for the build's page reader) and SOC 2 (the AICPA criteria are a download behind a
sign-in). ISO/IEC 27001 is sold by ISO, so its Annex A rows stay unverified until someone with a copy
of the standard confirms the four control numbers and titles.

A **stand-in** is a public reproduction read in place of an official text the build could not open,
so the product can be tested end to end. It does not make a control checked; it stays unverified
until the official text is read (`src/changeproof/standins.py`).
