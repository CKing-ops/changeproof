# Framework mapping

Generated by `scripts/framework_mapping.py` from `src/changeproof/frameworks.py`. Do not edit by hand.

changeproof's evidence comes in two halves that answer change-management controls together:

1. **What the change touches.** The impact predicate lists every entity that depends on the changed
   code, with a confidence tier and the dependency path to each one (built in Week 5,
   `tests/test_impact.py`).
2. **Proof that nothing else changed behaviour.** A behavioral-equivalence attestation for the code
   outside that impact set (**planned**, Weeks 8-9).

The impact set is the boundary the second half will test against. Rows below that need both halves
list both, with the equivalence half marked planned.

Each control lists the engine output that answers it and the test or exit check that proves the
engine produces that output. Outputs marked **planned** are not built yet.

**Status** is about the control itself. "checked" with a date means its ID and topic were read in
the linked source text on that date. **unverified** means they were not: they come from the
project's own knowledge and must be checked against the source before anyone relies on them
(project rule 6). The topic column is our own short label, not the control's wording.

Checked so far: the ECB IT Risk Questionnaire rows (fact-check of 2026-09-27) and the Delegated
Regulation (EU) 2024/1774 rows (Articles 6, 7, 16 and 17 and recital 9, read on EUR-Lex on
2026-10-01). Still unverified: DORA itself (Regulation (EU) 2022/2554; the EUR-Lex page did not
open), GDPR, SOC 2 (AICPA), NIST and CNSA 2.0 pages, which need the owner's approval to open from
the build environment. ISO/IEC 27001 is sold by ISO, so its Annex A rows stay unverified until
someone with a copy of the standard confirms the four control numbers and titles.
